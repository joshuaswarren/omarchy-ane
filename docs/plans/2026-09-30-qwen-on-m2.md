- **[V]** /var/tmp/qwen38-staged-<M1-host>/prog_NNN/model.mil and adjacent weights.bin are present for all 38 M1 programs. - **[V]** The real compiled ANECs are under /var/tmp/qwen-real-anec-h14/, generated from /var/tmp/qwen-real-hwx-h14/. Manifest index 20 has 20 tasks, three inputs, one output, 83,892,736 constant bytes, and an 83,900,608-byte ANEC. Its constant section corresponds to the real program-20 weights (83,890,880 bytes plus framing/alignment). This package is distinct from the earlier batch8 proxy. The converter manifest warns: tensor-to-channel identity is a size/order heuristic, verify binding at load time.
- **[V]** The real ANEC index-20 table says channel 5 is named t15 with shape [1,1,16,128], channel 6 is t2 with the same shape, channel 7 is t7 with shape [1,1,1,2048], and output channel 4 is named t0 with shape [1,1,1,2048]. M1 MIL declares inputs t7, t2, t0 and output t15. The shape-based correspondence used for the first run was M1 t0 → ANEC input slot 0/channel 5, M1 t2 → slot 1/channel 6, M1 t7 → slot 2/channel 7, ANEC output channel 4 → M1 t15. This mapping is **not yet numerically validated**.
- **[V]** The M1 program-20 MIL computes SiLU, L2 normalization and learned scale, projection, residual, another normalization, gated MLP, projection, and residual. The six BLOBFILE constants are listed below. Their BLOBFILE offsets point to 64-byte blob headers; constant data begins 64 bytes after each offset.
- **[V]** The old H14 batch8 proxy was built from synthetic A/D/E projection tests; its code emitted zero-filled test blobs and did not include trained RMS gamma. Do not use those proxy files for model-correctness measurements.
- **[V]** T6021 userspace tool accepts indexed ANEC inputs and outputs. The loader allocates one 16-KiB tile per channel even when logical data is 4 KiB; zero-pad each dense input to 16 KiB. The first unpadded attempt was rejected before CALLIO with “need at least 16384 bytes”, though the ANEC sections were loaded. The padded run completed and produced one 16-KiB output surface.

## M1 — class C / program 20

**Verdict: FAIL.** The real-weight ANEC loaded and returned output, but its output does not match the same-step M1 output or the exact fp64 MIL reference. Stop here; do not start M2/M3/M4 until the ANEC port binding or conversion is corrected and M1 passes.

- **[V]** M1 input arrays and output are staged under the private artifact path ~/.local/share/apple-silicon-lab/artifacts/QwenM2/2026-09-30-t6021-qwen-chain/prog020-classC/. Their hashes match the M1 program-20 golden banks. One ANEC package was submitted; LOADSEC records show its sections, and the two completed calls reused it. The successful calls recorded CALLIO for channels 5, 6, 7, and 4 at 16,384 bytes each. No EXCH failure or DART error appeared in the observed log tail.
- **[V]** First call: device output vs M1 golden, max absolute error 0.474609375, relative L2 0.2756553426, exact fp16 fraction 0.00048828125 (1/2048). Swapping the two equal-shape inputs did not improve the result: max absolute 0.455078125, relative L2 0.2758836011, exact fraction 0.
- **[V]** The fp64 reference follows the MIL graph and real weights.bin data, skipping each 64-byte BLOBFILE header. M1 golden vs fp64: max absolute 0.0050986026, relative L2 0.0112268657, exact fp16 fraction 0.02099609375. First M2 output vs fp64: max absolute 0.4724890215, relative L2 0.2756774076, exact fp16 fraction 0.00048828125. The M1 golden is much closer to the MIL reference; the M2 output is not an fp16-rounding discrepancy.
- **[I]** The channel-name inversion and explicit converter warning about heuristic tensor identity make port binding or conversion a likely cause. The two possible assignments for the same-shaped M1 t0 and t2 inputs were tried; neither matched. Root cause is unresolved.

**Exact next step:** after the lead releases the M2 for this work, resolve the H14 converter's tensor-to-channel identity for program 20 from source/task records, validate each physical channel mapping, then rerun only this program with the M1 vectors and exact reference. Do not proceed to M2–M4 before it matches the M1 golden within an operation-derived tolerance. The first rejected 4-KiB input attempt and the two successful 16-KiB surface calls consumed one distinct ANEC program against the 250-per-boot firmware limit.
